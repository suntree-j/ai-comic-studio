## 二、演示顺序（8 分钟版）

### 第 1 分钟 · 先讲问题，不讲功能

> "AI 画漫画，直接让模型画有三个必死问题：**一致性崩溃**（第 3 格换发色、第 8 格换衣服）、
> **不可控**（改一句台词要重出整页图，90 秒一张）、**不可复现**（同样输入两次结果不同）。"

**为什么这么开场**：让对方先认可问题是真实的，后面讲方案才有意义。
不要一上来就 show 界面。

### 第 2 分钟 · 一句话讲清核心思路

> "我的做法是类比 **Text-to-SQL**：不让 LLM 直接查数据库，而是让它产出 SQL；
> 同理，我不让 LLM 直接画漫画，而是让它产出 **Comic IR** —— 一个受 Schema 约束的中间层。
> 决策交给 LLM，渲染交给确定性引擎。"

**这是整个项目最值钱的一句话。** 说完停一下，看对方反应。

### 第 3–4 分钟 · 打开工作台，演示三个动作

**动作 ① 拖气泡**（10 秒）

在画布上把「你喜欢这柄冰晶刹弓…」那个气泡拖到别的位置。

> "气泡框直接拖，松手就 PATCH 到 JSON，页面图局部重渲染 —— **注意底图完全没变**。"
> "这就是对白分层存储的价值：改一句话、挪一个位置，只要 3 秒，不用重出图。"

**动作 ② 改台词**（10 秒）

右侧「本页对白」里把台词改几个字，失焦。

> "改完立刻重渲染。整本书 216 格，改 20 句原本要重出 20 页图，
> 现在只需要改 JSON 重排版。"

**动作 ③ 换说话人 → 看确认徽章变红**（15 秒）

把说话人下拉从「穆宁雪」换成「穆飞鸾」。

> "换人之后确认徽章自动从绿色变成『待确认』 —— **程序不猜谁在说话**。
> 未确认的说话人会被 IR-006 规则拦住，不允许进入渲染。"

**这三个动作是有意选的**：分别对应「可编辑」「低成本」「不猜」三个设计决策。

### 第 5 分钟 · 点「校验 IR」，展示规则引擎

点顶部「校验 IR」按钮，弹出规则面板。

> "这是 12 条业务规则，不是 JSON Schema。Schema 只能挡格式错误，
> 挡不住『格式正确但语义错误』。比如这条 IR-002：两人同框必须写明具体距离，
> 否则模型会把两人画得像在聊天。"
>
> "每条规则都带**修正建议** —— 这段文本就是回馈给 LLM 做自修复的内容。"

如果面板里是「校验通过」，就补一句：

> "规则不是摆设，我之前故意在示例数据里留了个错，它当场就抓出来了。"

### 第 6 分钟 · 讲一次真实失败（这是加分项）

切到 `docs/lessons.md`，讲**页码冻结**那一段：

> "这个项目的前身是一次真实产出：20 章、168 页、216 格。
> 中途用户说『第 77 页这句不对』，我删掉了那一页 —— **后面所有页码前移了**。
> 于是用户看到的第 77 页和我本地的第 77 页不再是同一页，
> 连续 3 轮沟通都对不上，最后整个项目放弃修正。"
>
> "所以这个版本里，页码一经分配**永久冻结**：删一格就把那页标成 empty 留空，
> 后面的页码一律不动。而且 —— **API 里刻意不提供任何修改页码的接口**。"

**为什么这段最有说服力**：它证明的不是"我会写代码"，
而是"我能从失败里提炼出可复用约束"。

### 第 7 分钟 · 讲工程严谨性

> "166 个单元测试 + 25 项端到端验收 + 28 项线上自检。"
>
> "而且有三个坑是**本地全绿、部署才炸**的，我写进测试挡住了：
> 缺 numpy、缺中文字体、字体探测 API 变更。
> 其中中文字体那个最阴 —— 气泡里的中文全渲成方块，但**接口返回 200、日志干干净净**，
> 只有肉眼看图才发现。这叫静默降级，比报错危险得多。"

### 第 8 分钟 · 收尾给链接

> "GitHub 和在线 Demo 都在简历上，代码是能直接 clone 跑的 ——
> `python examples/minimal/run_full.py` 完全离线就能跑通
> 『小说 → IR → 校验 → 渲染 → PDF』全流程，不需要任何 API key。"

## 三、工作台的设计

### 整体：三栏 + 顶栏

```
┌────────────────────────────────────────────────────────────────────┐
│  ◆ AI Comic Studio  漫画工作台      [showcase 9页▼] [校验IR][出图][导出PDF] │
├──────────────┬─────────────────────────────────┬───────────────────┤
│  项目概览      │  ‹上一页   第 2/9 页   下一页›    │  本页对白          │
│  ┌────┬────┐ │  ☑ 显示气泡框                    │  ┌─────────────┐  │
│  │ 9  │ 8  │ │                                 │  │说话人 ▼ [已确认]│  │
│  │页数│镜头│ │   ┌─────────────────────────┐   │  │台词…          │  │
│  ├────┼────┤ │   │ ┌────────┐              │   │  │☐ 锁定         │  │
│  │ 8  │ 3  │ │   │ │气泡 穆宁雪│───┐        │   │  └─────────────┘  │
│  │对白│章节│ │   │ └────────┘   │        │   │  ┌─────────────┐  │
│  └────┴────┘ │   │         ┌────▼─────┐  │   │  │穆飞鸾 ▼ [已确认]│  │
│              │   │         │气泡 穆飞鸾│  │   │  │解决掉他们。   │  │
│  角色         │   │         └──────────┘  │   │  └─────────────┘  │
│  穆宁雪 穆飞鸾 │   └─────────────────────────┘   │                   │
│  穆隐凤 莫凡   │        ↑ 虚线框 = 气泡可拖拽        │  本页镜头          │
│              │        ● 圆点   = 箭头尾端可拖拽     │  ch2436_P001      │
│  页码（冻结）  │                                 │  极远景·2048x1400 │
│  1 2 3 4 5   │                                 │  穆宁雪           │
│  6 7 8 9     │                                 │  极远景：穆宁雪…   │
│  ↑ 只能点，不能改│                                 │  技能：ice_bow    │
└──────────────┴─────────────────────────────────┴───────────────────┘
```

**左栏**：项目概览（页/镜头/对白/章节）· 角色清单（用了的标白，没用的标灰）· 页码
**中栏**：画布 + 页面切换 + 「显示气泡框」开关
**右栏**：本页对白（逐条可编辑）· 本页镜头（只读信息卡）
**顶栏**：项目切换 · 校验 IR · 出图 · 导出 PDF

### 核心技术决策一：渲染在服务端

**前端只发坐标，不实现任何排版逻辑。**

```javascript
// 拖完气泡，前端只发一个坐标
await api(`/dialogue/${panelId}/${utt.id}`, {
  method: 'PATCH',
  body: JSON.stringify({ box: { x, y } })     // ← 只有坐标
});
refreshPageImage();                            // 然后重新拉一张服务端渲染好的图
```

```python
# 服务端收到坐标 → 写回 JSON → 清缓存 → 重新渲染那一页
@app.patch("/api/projects/{name}/dialogue/{panel_id}/{utt_id}")
def patch_utterance(...):
    items[panel_id] = [new if u.id == utt_id else u for u in items[panel_id]]
    save_project(project)      # 落盘
    invalidate(name)           # 清缓存
    return {"ok": True, "utterance": new.model_dump(mode="json")}
```

**为什么不前端排版？** 因为那样会有两套渲染逻辑（前端一套、CLI 一套），
迟早不一致。现在的保证是：**工作台所见 = 命令行产出**。

### 核心技术决策二：编辑只改 JSON，不碰图片

所有编辑接口都只写 IR：

| 动作 | 写回哪 | 图片 |
|---|---|---|
| 拖气泡 | `dialogue.json` 的 `bubble.box` | 不动 |
| 拖箭头 | `dialogue.json` 的 `bubble.tail` | 不动 |
| 改台词 | `dialogue.json` 的 `text` | 不动 |
| 换说话人 | `dialogue.json` 的 `who` + `confirmed=false` | 不动 |
| 锁定 | `dialogue.json` 的 `locked` | 不动 |
| 改分镜 | `storyboard.json` | 不动 |

**这条规则的价值**：素材随时可以由 IR 重生，反过来不行。
（上一次项目把改动都烧进图里，删掉目录后全部对白数据永久丢失。）

### 核心技术决策三：页码只读

左栏页码**只能点，不能改**。而且 —— **API 里根本没有改页码的接口**：

```python
# 服务端实际注册的路由（没有任何 layout / page 的写接口）
GET    /api/projects/{name}                      # 读
GET    /api/projects/{name}/pages/{n}.png        # 只读渲染
PATCH  /api/projects/{name}/dialogue/{pid}/{uid} # 只能改对白
PATCH  /api/projects/{name}/panels/{id}          # 只能改分镜
# ↑ 没有 PATCH /layout，也没有 PATCH /pages
```

而且有一条测试专门盯这个：

```python
def test_backend_has_no_page_mutation_route():
    """★ 页码冻结：后端不得提供任何修改页码的接口"""
    for r in app.routes:
        if path.endswith("/pages") or path.endswith("/page"):
            assert methods <= {"GET", "HEAD", "OPTIONS"}
```

**冻结机制靠三层保证**：数据层（`Layout` 强制页码连续唯一）+ 规则层（IR-009/010）+ 接口层（不提供写接口）。

### 核心技术决策四：说话人必须人工确认

```
┌──────────────────────────────┐
│ 穆宁雪          ▼   [已确认]   │   ← 下拉选择 + 状态徽章
├──────────────────────────────┤
│ 你喜欢这柄冰晶刹弓，作为多年   │   ← 台词可编辑
│ 的朋友，我自然亲手赠你。       │
├──────────────────────────────┤
│ ☐ 锁定          ch2436_P001  │   ← 锁定后自动布局不再改动它
└──────────────────────────────┘
```

换了说话人，`confirmed` 自动置 `false`，徽章从绿变黄：

```javascript
sel.onchange = async () => {
  await api(..., { body: JSON.stringify({ who: sel.value }) });
  u.confirmed = false;      // ← 换人必须重新确认
  toast('说话人已改，需重新确认');
};
```

**为什么**：程序无法可靠判断「这句话是谁说的」。
IR-006 会拦住未确认的说话人，不进入渲染。

### 核心技术决策五：气泡布局的内容能量最小化

前端只画**编辑框**（虚线框），真实气泡位置由服务端算法决定：

```
能量 = 0.6 × 与画面中位色的差异 + 0.4 × 边缘梯度
```

气泡落在**画面最空、最不打扰人物**的位置。配 `detect_person_side()`：
肤色 + 深色发/衣 + 红色围巾，**排除雪白背景**
（雪景里不排除的话整幅都是「亮」的，判不出人物在哪）。

### 为什么不写 React

**取舍**：这个项目要「克隆下来就能跑」。

- 纯静态前端 → 无需 `npm install`、无需构建、无 node_modules
- 工作台总共 725 行（`app.js` 535 + `index.html` 71 + `style.css` 119）
- Docker 镜像小得多，演示零门槛

后端 API 已经设计成与前端无关，等交互复杂度上来（多选、撤销栈、时间轴 diff）再迁 React 也不迟。

**如果被问「为什么不用框架」**，就答这个 —— 这是清楚的技术判断，不是不会。

## 四、工作台的 API（一共 16 个）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 健康检查 + 当前生图服务 |
| GET | `/api/config` | 前端运行时配置（子路径前缀） |
| GET | `/api/projects` | 项目列表 |
| GET | `/api/projects/{name}` | 完整 IR + 统计 |
| POST | `/api/projects/{name}/validate` | 跑 12 条规则 |
| GET | `/api/rules` | 规则表 |
| GET | `/api/projects/{name}/pages/{n}.png` | 渲染第 n 页 |
| GET | `/api/projects/{name}/panels/{id}.png` | 单格底图 |
| **GET** | **`/api/projects/{name}/prompt/{id}`** | **查看该格最终提示词（透明化）** |
| PATCH | `/api/projects/{name}/dialogue/{pid}/{uid}` | 改对白 |
| PATCH | `/api/projects/{name}/panels/{id}` | 改分镜 |
| POST | `/api/projects/{name}/render` | 后台出图（返回 task id） |
| GET | `/api/tasks` `/api/tasks/{id}` | 任务进度 |
| POST | `/api/projects/{name}/export` | 导出 PDF / 长图 |
| GET | `/api/projects/{name}/download/...` | 下载产物 |

**「提示词透明化」接口值得单独讲**：

```bash
curl "http://36.151.150.140/comic/api/projects/showcase/prompt/ch2436_P001"
```

直接返回最终送给生图模型的那段提示词。**为什么重要**：AI 项目最难排查的是
「为什么画出来是这样」—— 这个接口把黑盒打开，能看到共享风格块、角色标准块、
本格构图、禁止文字条款是怎么拼起来的。

## 六、可能被问的问题（提前想好）

| 问题 | 回答要点 |
|---|---|
| **为什么不让 LLM 直接画？** | 一致性不可控、改动成本高、不可复现。类比 Text-to-SQL：让 LLM 出 SQL 而不是直接出结果 |
| **IR 为什么是 4 个文件？** | 变更频率不同：bible 几乎不变、storyboard 少变、dialogue 常改、layout 冻结 |
| **12 条规则怎么来的？** | 全是从真实项目的失败里提炼的，每条能讲一个具体事故 |
| **自修复会不会死循环？** | 有 `max_rounds`，超了标 `pending_human`，**不硬渲染** |
| **页码冻结不浪费空间吗？** | 会浪费一点，但比「所有人对不上页码」便宜得多 |
| **怎么保证可复现？** | 渲染是纯函数，有逐像素一致的测试 |
| **上线踩过什么坑？** | 三个「本地全绿、部署才炸」：缺 numpy、缺中文字体、字体探测 API 变更。**重点讲静默降级那个** |
| **服务器上有别人的生产系统怎么办？** | 只追加子路径、先备份、`nginx -t` 通过才 reload、端口避开 |
| **为什么不用 React？** | 要「克隆就能跑」，725 行静态前端零构建；后端 API 与前端无关，要迁移随时可以 |
| **Demo 的画面是 AI 画的吗？** | ⚠️ **如实说**：画面来自已有的成品漫画，**气泡与排版**是本系统渲染的。可以补一句：「这本身也是个技术点 —— 能把已有漫画的对白抽成结构化数据、重新排版、并自动避开原图已烧入的文字」 |
| **做了多久？** | 如实说（提交记录都在，不会说谎） |
| **有什么没做完？** | 如实说：还没接真实生图跑完整闭环；Docker 镜像没实测构建过（本机 Docker 守护进程起不来） |
