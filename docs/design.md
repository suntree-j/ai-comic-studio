# AI Comic Studio · 方案设计

> 小说 → 漫画 的可复用开源方案
> 核心命题：**如何让 LLM 稳定地把散文变成可渲染、可编辑、可复现的漫画结构**

---

## 一、一句话定位

**AI Comic Studio = Text-to-Storyboard Agent + 确定性渲染引擎 + 可视化工作台**

```
小说文本 ──[AI 改漫 Agent]──▶ 漫画中间表示 (Comic IR) ──[渲染引擎]──▶ 漫画 PDF
                                      ▲
                                      │
                              [可视化工作台] 人工微调
```

**不是**「让 AI 直接画漫画」，而是「让 AI 产出**结构化剧本**，由确定性引擎渲染」——
这是本方案与同类项目的根本区别，也是它可复现、可编辑、可用于生产的原因。

---

## 二、核心洞察：为什么需要 IR（中间表示）

### 2.1 直接生成路线的三个必死问题

| 问题 | 现象 | 根因 |
|---|---|---|
| **一致性崩溃** | 同一角色第 3 格换发色、第 8 格换衣服 | 每次生成都是独立的，没有持久状态 |
| **不可控** | 想改一句台词要重出整页图 | 对白被烧进像素 |
| **不可复现** | 同样输入两次结果不同 | 全流程都是随机采样 |

### 2.2 IR 方案如何解决

```
┌──────────────────────────────────────────────────────────┐
│  Comic IR（受约束的中间表示）                              │
│                                                          │
│  ① Storyboard  每格画什么  → 决定构图，不决定像素          │
│  ② Dialogue    谁说哪句、放哪 → 与画面分离                │
│  ③ Bible       角色/场景的持久状态 → 一致性由它保证        │
│  ④ Layout      页码/分卷/页序 → 冻结，永不重排            │
└──────────────────────────────────────────────────────────┘
           ▲                                    │
      LLM 只写这里                        渲染器只读这里
   （受 JSON Schema 约束）            （纯函数，确定性输出）
```

**类比 Text-to-SQL**：
- 不让 LLM 直接查数据库，而是让它产出 **SQL**（受 schema 约束的中间层）
- 不让 LLM 直接画漫画，而是让它产出 **Comic IR**（受 schema 约束的中间层）

**收益**：
- ✅ **可校验**：IR 有 schema，能在渲染前发现 90% 的错误
- ✅ **可修复**：校验失败 → 把错误喂回 LLM 让它修（Self-Repair）
- ✅ **可编辑**：改 IR 一句话 → 3 秒重渲染，不用重出图
- ✅ **可复现**：同 IR + 同素材 → 同输出（渲染是纯函数）

### 2.3 IR 的三层约束（这是本项目的技术核心）

```
第 1 层  JSON Schema 约束
         └ 字段类型、枚举、必填 —— 挡掉格式错误

第 2 层  业务规则校验（Validator）
         └ 角色是否在 Bible 里？
         └ 说话的箭头是否指向画面内的人？
         └ 对白能否在原文找到？
         └ 页码是否连续、有无重复引用？

第 3 层  LLM 自修复（Repair Loop）
         └ 校验失败 → 错误信息 + 原文 回喂 → 重新产出
         └ 最多 N 轮，仍失败则标记 pending 交人工
```

## 五、AI 改漫 Agent 设计

### 5.1 Agent 的五个技能

```
┌───────────────────────────────────────────────────────────────┐
│  输入：小说原文（任意长度）                                      │
└───────────────────────┬───────────────────────────────────────┘
                        ▼
  ┌─────────────────────────────────────────────────────────┐
  │ Skill 1 · 章节切分                                        │
  │   长文本 → 有戏剧单元的章节                                  │
  │   依据：场景转换 / 时间跳跃 / 视角切换 / 章节标题             │
  └───────────────────────┬─────────────────────────────────┘
                          ▼
  ┌─────────────────────────────────────────────────────────┐
  │ Skill 2 · 分镜生成（Text → Storyboard）                    │
  │   输入：原文 + bible（已有角色/场景/风格）                   │
  │   输出：storyboard.json                                  │
  │   ★ 强制约束：景别枚举 / 两人同框必填 distance /             │
  │              同一角色相邻格不得同表情 / 战斗格填 damage_level │
  └───────────────────────┬─────────────────────────────────┘
                          ▼
  ┌─────────────────────────────────────────────────────────┐
  │ Skill 3 · 对白抽取（原文 → Dialogue）                      │
  │   ★ 说话人判定规则：                                       │
  │     引号紧邻的人名 + 说话动词 → 该人是说话人                 │
  │     「……对XX说道」→ XX 是听者，不是说话人                   │
  │     反向校验：句中其他人名 + 原文上下文                       │
  │   ★ 输出必须带 source_span，validator 会回原文核对           │
  └───────────────────────┬─────────────────────────────────┘
                          ▼
  ┌─────────────────────────────────────────────────────────┐
  │ Skill 4 · 角色一致性追踪（State Tracker）                   │
  │   跨格维护每个角色的：受伤状态 / 服装 / 情绪轨迹              │
  │   ★ 例：左肩→右腰的霜白伤口，从 ch2429 起持续到 ch2432       │
  │        每格提示词自动带上「该角色此刻仍有此伤」               │
  └───────────────────────┬─────────────────────────────────┘
                          ▼
  ┌─────────────────────────────────────────────────────────┐
  │ Skill 5 · 校验与自修复（Validator + Repair）                │
  │   ① Schema 校验  ② 业务规则校验  ③ 失败回喂 → 重产          │
  │   ④ 超轮次 → 标记 pending，进人工队列                        │
  └─────────────────────────────────────────────────────────┘
```

### 5.2 提示词组装（三段式）

每格的最终提示词 = **共享风格块 + 角色标准块 + 本格构图 + 禁止文字**

```python
def build_prompt(panel, bible) -> str:
    parts = []
    # ① 共享风格块（全篇逐字相同）
    parts.append(bible.style.shared_block)
    # ② 角色标准块（从 bible 取，逐字拼接，绝不改写）
    for c in panel.cast:
        ch = bible.characters[c.id]
        block = ch.appearance.text
        if c.variant and c.variant != "default":
            block += "\n【本格形态】" + ch.variants[c.variant].override
        if ch.state.injuries:                      # ★ 状态追踪
            block += "\n【该角色当前伤情】" + "；".join(
                i.desc for i in ch.state.injuries if not i.healed)
        parts.append(block)
    # ③ 本格构图（景别/位置/距离/动作/背景/氛围）
    parts.append(render_composition(panel))
    # ④ 禁止文字（★ 防止对白重复的关键）
    parts.append(bible.style.no_text_rule)
    return "\n\n".join(parts)
```

### 5.3 校验规则（Validator）—— 这是项目的护城河

| 类别 | 规则 | 违反后果 |
|---|---|---|
| **引用完整性** | `cast[].id` 必须在 bible 中存在 | 否则出图会换人 |
| **对白可追溯** | `dialogue.source_span` 指向的原文必须包含该句 | 防 LLM 编造台词 |
| **说话人已确认** | `confirmed == true` 才能渲染 | 防张冠李戴 |
| **距离必填** | `len(cast) >= 2` 时 `distance` 不能为空 | 防两人画得像聊天 |
| **表情不重复** | 同一角色相邻两格 `emotion_hint` 不得相同 | 防全程一个表情 |
| **损伤单调** | `damage_level` 不得无故回落 | 防伤口自愈 |
| **页码冻结** | `layout.pages[].page` 连续且唯一 | 防页码错位 |
| **气泡不越界** | `box`/`tail` 在 [0,1] 内 | 防气泡跑出画面 |
| **无文字残留** | 生图结果经「小连通域检测」判定无文字 | 防对白重复 |

### 5.4 自修复循环

```python
MAX_REPAIR = 3
for attempt in range(MAX_REPAIR):
    ir = await llm.generate(prompt, schema=ComicIR)
    errors = validate(ir, bible)
    if not errors:
        break
    prompt = repair_prompt(original=prompt, bad_output=ir, errors=errors)
else:
    ir.status = "pending_human"     # 交人工，不硬着头皮渲染
```

## 六、渲染引擎

### 6.1 纯函数原则

```python
render_page(layout_page, storyboard, dialogue, bible, assets) -> Image
```
**同输入必同输出**，不依赖随机数、不依赖当前时间。这样：
- 可复现（换机器也一样）
- 可缓存（IR 没变就跳过）
- 可测试（Golden Image 对比）

### 6.2 渲染流水线

```
① 载入该页所有单格图，统一缩放到目标宽度 2480px
② 叠加特效层（速度线 / 拟声词）
③ 叠加技能名标签
④ 叠加对白气泡：
     ├ 气泡放置：内容能量最小化（避开人物）
     ├ 侧向判定：气泡放说话人的相反侧
     └ 同格多气泡：强制分侧 / ≥5 个固定竖排
⑤ 纵向拼接成页
⑥ 输出
```

### 6.3 气泡放置算法

```
score(位置) = 0.6 × 色彩差异 + 0.4 × 边缘梯度
            + 重叠惩罚
            - 说话人反向加成

候选位置：tl / tr / bl / br / tm / bm
```
目标：气泡落在**画面最空、最不打扰人物**的位置。

### 7.2 关键交互设计（来自实战教训）

| 交互 | 为什么 |
|---|---|
| **气泡可拖拽 + 可锁定** | 自动放置必然出错，人工调完必须锁定 |
| **说话人下拉选择** | 不能让程序猜，必须人指定 |
| **箭头尾端可拖动** | 「指向谁」是最常需要微调的 |
| **页码只读显示** | 页码冻结，不允许在 UI 里改 |
| **每页显示 IR diff** | 让人知道这次改动影响了什么 |
| **一键重渲染当前页** | 改一句话 3 秒看效果 |

| 层 | 选型 | 理由 |

├─────────────────────────────────────────────────┤

### 8.2 成本控制（Demo 站的关键）

| 手段 | 说明 |
|---|---|
| **出图结果全缓存** | Demo 站只读预置案例，不实时出图 |
| **在线试玩限流** | 每 IP 每天 N 次；只跑「分镜生成」（便宜），不跑「出图」（贵） |
| **生图服务可插拔** | Demo 用便宜模型，本地部署可换好的 |
| **静态化优先** | 成品页预渲染成静态图 + CDN |

## 十一、简历呈现角度

### 一句话
> **设计并实现 AI Comic Studio：一个把小说自动改编成漫画的开源系统。核心是定义了受 Schema 约束的「漫画中间表示（Comic IR）」，让 LLM 只负责创作决策、确定性引擎负责渲染，从而解决了 AI 生成漫画的一致性、可编辑性与可复现性三大难题。**

### 可量化的点
| 指标 | 值 |
|---|---|
| 端到端产出 | 20 章 / 168 页 / 216 格完整漫画 |
| Agent 校验规则 | 9 类，拦截率 XX% |
| 自修复成功率 | XX% |
| 单页重渲染 | 3 秒（vs 重出图 90 秒） |
| IR 层代码 | XX 行 + XX 测试 |

### 技术亮点（面试可深入）
1. **受约束生成**：LLM 输出受 JSON Schema + 业务规则双重约束
2. **自修复循环**：校验失败自动回喂重产，而非直接失败
3. **状态追踪**：跨格维护角色伤情/服装/情绪，解决长程一致性
4. **纯函数渲染**：确定性、可缓存、可 Golden 测试
5. **可插拔架构**：LLM / 生图服务都是适配器，不锁定厂商
