# 漫画工作台

> 可视化编辑 Comic IR：拖气泡、改说话人、调箭头、一键重渲染、导出 PDF。

---

## 快速开始

```bash
# ① 生成示例项目（含 IR 文件 + Mock 素材）
python scripts/make_demo_project.py

# ② 启动工作台
python -m apps.api.server --port 8000

# ③ 打开 http://127.0.0.1:8000
```

一条命令即可看到完整功能，**不需要任何 API key**。

## 四个关键交互（都来自实战教训）

### ① 气泡可拖拽 + 可锁定

自动布局算法再好也会有偏差（画面内容千变万化）。
所以：**拖动调整 → 点「锁定」→ 之后重渲染不再改动它**。

锁定状态在 IR 里是 `locked: true`，在画布上是**绿色实线框**。

### ② 说话人必须人选

程序无法可靠地判断「这句话是谁说的」。
工作台把它做成**下拉选择**，且改了说话人会自动把 `confirmed` 置为 `false`
—— **未确认的说话人不会进入渲染**（IR-006 会拦住）。

### ③ 页码只读

页码冻结机制的 UI 体现：**左栏页码只能点，不能改**。
删除某格只会在 `layout.json` 里标 `empty`，其余页码永不重排。

### ④ 渲染在服务端

前端只发坐标（`{box: {x, y}}`），排版由服务端统一计算。
这保证**工作台所见 = CLI 产出**，不会出现两套渲染逻辑不一致。

## API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/projects` | 项目列表 |
| GET | `/api/projects/{name}` | 完整 IR + 统计 |
| POST | `/api/projects/{name}/validate` | 跑 12 条规则校验 |
| GET | `/api/projects/{name}/pages/{n}.png` | 渲染第 n 页 |
| GET | `/api/projects/{name}/panels/{id}.png` | 单格底图 |
| GET | `/api/projects/{name}/prompt/{id}` | **查看该格最终提示词**（透明化） |
| PATCH | `/api/projects/{name}/dialogue/{pid}/{uid}` | 改对白（说话人/文字/位置/箭头/锁定） |
| PATCH | `/api/projects/{name}/panels/{id}` | 改分镜（距离/动作/氛围/损伤） |
| POST | `/api/projects/{name}/render` | 后台出图（返回 task id） |
| GET | `/api/tasks/{id}` | 任务进度 |
| POST | `/api/projects/{name}/export` | 导出 PDF / 长图 |
| GET | `/api/projects/{name}/download/...` | 下载产物 |

**注意**：API 里**没有**改页码的接口 —— 冻结机制在接口层面就锁死了。

## 为什么不用 React

**取舍**：这个项目要「克隆下来就能跑」。
纯静态前端 → 无需 `npm install`、无需构建、无 node_modules，
Docker 镜像也小得多，展示时零门槛。

等交互复杂度上来（多选、撤销栈、时间轴 diff）再迁 React 也不迟 —— 
后端 API 已经设计成与前端无关。
